# Security Policy

ACTIVE BRAINS Technologies takes the security of our software, infrastructure, and user data seriously. We appreciate the responsible disclosure of security vulnerabilities by ethical security researchers and developers.

---

## Supported Versions

We provide security updates and patches for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| `main` (Latest) | :white_check_mark: |
| Active Releases (< 6 months) | :white_check_mark: |
| Older Versions / Pre-releases | :x:                |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, please use one of the following secure disclosure channels:

### 1. GitHub Private Vulnerability Reporting (Preferred)
You can report vulnerabilities directly and securely to our engineering team within GitHub:
1. Navigate to the **Security** tab of this repository.
2. Select **Advisories** under the *Reporting* sidebar.
3. Click **Report a vulnerability** to open a confidential report draft.

### 2. Direct Security Contact
If you cannot use GitHub's private vulnerability reporting, please email our security operations team:
- **Email**: [solution@activebrains.co.uk](mailto:solution@activebrains.co.uk)
- **Subject Line**: `[SECURITY VULNERABILITY] <Brief Description of the Issue>`

### What to Include in Your Report
To help us triage and resolve the issue quickly, please provide:
- A clear description of the vulnerability and its potential impact.
- Step-by-step reproduction instructions or a minimal Proof of Concept (PoC).
- Relevant URLs, API endpoints, parameters, or code references.
- Any suggested mitigations or patches (if available).

---

## Response & Disclosure Process

When a report is received, our security team follows this process:
1. **Acknowledgement**: We aim to acknowledge receipt of your report within **24 to 48 hours**.
2. **Investigation & Triage**: We will investigate, confirm reproducibility, and determine the severity rating according to the CVSS framework.
3. **Resolution**: We will engineer, test, and validate a fix in a private staging environment.
4. **Coordinated Disclosure**: Once the fix is published to production, we will publish a security advisory crediting you for the responsible discovery (unless you request anonymity).

---

## Responsible Disclosure & Safe Harbor

We consider security research conducted under this policy to be authorized. When conducting security assessments:
- Make a good faith effort to avoid privacy violations, data destruction, and interruption or degradation of our production services.
- Only interact with test accounts you own or have explicit permission to use.
- Give us reasonable time to remediate the vulnerability before disclosing any details publicly.

Thank you for helping us keep ACTIVE BRAINS secure!
